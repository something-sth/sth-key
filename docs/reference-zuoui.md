## ⚠️ 这个目录是干什么的

**只用来参考悬浮窗的视觉与布局**，目标是把 `Touching` 面板与将来的游戏内悬浮窗做得不那么丑。

## ⚠️ 明确边界（重要）

| 可以做 | 不可以做 |
|---|---|
| 看 `res/values`、`res/drawable` 里的**颜色/圆角/间距** | 看任何注入、内存、反检测、hook 相关实现 |
| 看自定义 View 的**绘制参数**（圆角、阴影、尺寸）| 把它的业务逻辑"改造"进我们的项目 |
| 参考**信息层级与交互骨架**（卡片分组、悬浮球、折叠）| 复制它的代码文件 |

⚠️ 我们是正经的按键显示工具:**不接入任何作弊逻辑**。
这个目录的存在只有一个理由 —— UI 观感。**以后上下文不够时，看这段就够了。**
总结成一句话: **这是"UI 参考书"，不是"功能来源"。**

## 它的悬浮 UI 由哪些 View 组成（仅名字，供对照）

| 文件 | 大致角色（按名字推断，未读逻辑） |
|---|---|
| `FloatBallView` | 悬浮球（收起态）|
| `MenuView` | 主菜单容器（圆角 8dp）|
| `CardMenuView` | 卡片式菜单（圆角 22dp、内部元素 13/18dp）|
| `ModuleCardView` | 模块卡片（圆角 14dp，含开关滑轨）|
| `ModuleItemView` | 卡片内条目（圆角 8dp）|
| `SubMenuPanel` | 二级面板 |
| `IslandOverlay` | 药丸式提示（四周留 12dp）|
| `NotificationView` | 通知条 |
| `LiveBlurView` / `WindowBlur` | 背景模糊（**我们暂不采用**，见下）|

## 已提取的视觉参数（可验证的具体值）

| 项 | 值 | 备注 |
|---|---|---|
| 主菜单圆角 | **8dp** | `MenuView.CORNER_RADIUS_DP = 8f` |
| 卡片菜单圆角 | **22dp** | `CardMenuView` 容器 |
| 卡片内元素圆角 | **13dp**（指示块）/ **18dp**（头像块）| |
| 模块卡片圆角 | **14dp** | `ModuleCardView` |
| 卡片内条目圆角 | **8dp** | `ModuleItemView.CORNER_RADIUS_DP = 8` |
| 分割线 | **10% 黑**（`0x1A000000`）| 很克制 |
| 卡片进入动画 | **300ms** | 每批 3 张（`CARDS_PER_BATCH = 3`）|
| 药丸提示外边距 | **12dp** | `IslandOverlay.WIN_PAD` |

⚠️ `res/values/colors.xml` 是**空文件** —— 它的配色全部写在代码里（`0xFF...` 常量），
所以要提取色板得逐个文件读数值。**这一项等真正开始做面板时再补齐**。

## 我们打算借鉴 / 不借鉴

| 借鉴 | 理由 |
|---|---|
| 圆角层级（8 / 14 / 22dp）| 层次分明又不浮夸，适合我们这种工具 |
| 10% 分割线 | 比 Material 默认分割线更轻，不打断视觉 |
| 卡片分批进入（300ms、3 张一批）| 面板项多时不会一次弹出十几张 |
| 悬浮球 → 面板的展开方式 | 正是我们 `Touching` 面板想要的入口形态 |
| 药丸式提示 | 适合"方向不符"这种一句话提示 |

| **不借鉴** | 理由 |
|---|---|
| 背景实时模糊（`LiveBlurView`/`WindowBlur`）| 需要 `RenderEffect`/`SurfaceControl`，悬浮窗上代价高、兼容性差 |
| 彩虹文字等装饰 | 与工具气质不符 |
| 深色偏黑客风的整体调性 | 我们的应用是浅色卡片风，只借"结构"不借"性格" |
