# 自定义 Key：触摸区域对接方案（设计稿）

> 状态:**方案讨论稿，未写代码**
> 目标:让新编辑器（单容器 + 胶囊面板）支持**自定义 Key 样式**的触摸区域 ——
> 也就是"新建区域 / 绑定组件 / 删除区域"这三件旧编辑器才有的能力。

---

## 1. 两种样式的本质区别（决定了 UI 复杂度）

| | 触屏样式（已对接） | 自定义 Key（本方案） |
|---|---|---|
| 区域从哪来 | **槽位决定**，数量与归属固定 | **用户自己加**，可增删 |
| 绑定谁 | 槽位天然对应按键 | 要**手动选组件**（按键/文本/摇杆）|
| 数量 | 5 个左右 | 用户想加多少加多少 |
| 是否需要"加/删/绑定" | ❌ 不需要 | ✅ **核心功能** |

⚠️ 所以自定义 Key 的胶囊不能只是"每行一个滑块"，还要塞进三个动作。

---

## 2. 胶囊宽度不够怎么办 —— **手风琴列表**

胶囊展开宽度固定 190dp（用户定的统一宽度）。这么窄放不下"名称 + 滑块 + 绑定 + 删除"。

方案:**行内只放摘要，点行展开细节**。

```
┌ 触摸区域                    ▾ ┐   ← 头部（点一下收起）
│ ＋ 轮盘    ＋ 按键            │   ← 两个新建按钮（sthtool 风格的小胶囊按钮）
├───────────────────────────────┤
│ ● 轮盘区域   已绑定 2 个   ▸  │   ← 行（收起态）
│ ● 按键区域   未绑定 ⚠      ▸  │
│ ● 按键区域   已绑定 1 个   ▸  │
│                               │
│   （点某一行 → 该行展开）      │
│ ● 按键区域   已绑定 1 个   ▾  │
│   ├ 大小  ────●────  28.5%   │   ← 滑块（唯一尺寸入口）
│   ├ [绑定组件]      [删除]    │
│   └ 已绑定：W  ↑ / 文本  →    │   ← 绑定摘要（可点进去改）
├───────────────────────────────┤
│              [不保存] [保存退出] │
└───────────────────────────────┘
```

要点:

| 项 | 说明 |
|---|---|
| 色点 | 与屏幕上方块颜色对应（旧编辑器就有，用户靠颜色认）|
| 绑定摘要 | **"未绑定 ⚠"必须显眼** —— 旧模型最坑的就是"画着但没绑，按了没反应" |
| 手风琴 | 同时只展开一行，避免面板变超长 |
| 滚动 | 区域多于 4 个时列表滚动（沿用现在的 ScrollView）|

---

## 3. 绑定组件:胶囊内**二级视图**

点「绑定组件」→ 胶囊内容**切换**成选择页（不是弹新窗口，避免多窗口串味）:

```
┌ ← 绑定「按键区域」            ┐
│ 当前布局里的组件：             │
│ ☑ W                            │
│ ☑ 文本「CPS」                  │
│ ☐ 摇杆（左）                   │
│                               │
│ 方向（仅轮盘区域需要）：        │
│ [无] [↑] [↓] [←] [→]          │
├───────────────────────────────┤
│              [取消] [确定]     │
└───────────────────────────────┘
```

规则（沿用旧模型的语义）:

| 区域类型 | 可绑定的组件 | 方向 |
|---|---|---|
| `BUTTON` | 按键 / 文本 / 摇杆（按下即触发）| 不需要 |
| `MOVE_STICK` | 按键 / 文本（方向匹配才算）/ 摇杆（推它）| 需要（↑↓←→）|

⚠️ 摇杆组件对 `BUTTON` 类型"不适配"（没有按下这回事），列表里要么禁用要么过滤 —— **默认过滤**，避免用户选了没效果。

---

## 4. 新建区域

- 两个按钮:`＋ 轮盘` / `＋ 按键`（对应 `MOVE_STICK` / `BUTTON`）
- 新区域默认：屏幕中央偏下、`SIZE_DEFAULT`、**自动展开该行并提示"未绑定"**
- id 生成：沿用现有的 `CustomTouchRegion` id 规则（`region_xxx`），**不要复用槽位 id**

⚠️ 不加"确认对话框"—— 加了再删就是了，弹窗只会打断节奏（旧编辑器那次"两个按钮而不是一个按钮+对话框"就是踩过闪退的坑）。

---

## 5. 删除区域

- 行展开后才有「删除」，**立刻生效**（不弹确认），但**保存退出前不写盘**
- 删除后如果列表空了，直接回到"没有区域"的空态提示 + 两个新建按钮

⚠️ 删除是"内存里删"，点「不保存退出」会全部还原 —— 与拖动/尺寸的语义一致。

---

## 6. 保存

| 动作 | 行为 |
|---|---|
| 保存退出 | 写 `custom.touchRegions` → `OverlayService.refresh()` → Toast「触摸区域已保存」|
| 不保存退出 | 不写盘，丢弃全部改动 |

⚠️ 与触屏样式共用**同一套** `pendingItems` / 快照对比逻辑，只是字段来源从 `touch.regions` 换成 `custom.touchRegions`。

---

## 7. 数据映射

| 编辑器内部 | 触屏样式 | 自定义 Key |
|---|---|---|
| `Item.id` | 槽位 id（`@move` / `W` …）| `CustomTouchRegion.id` |
| `Item.label` | 槽位名 | 「按键区域」/「轮盘区域」+ 绑定摘要 |
| 尺寸 | `TouchRegionBinding.size` | `region.size` |
| 绑定 | 无 | `bindings: List<CustomTouchRegionBinding>` |

⚠️ 需要在 `Item` 上补两个字段:`kind`（轮盘/按键）与 `bindings`（自定义 Key 用，触屏样式恒空）。

## 10. 实施记录（2026-11-14）

### 已完成

| 项 | 内容 |
|---|---|
| 8 向方向 | `TouchDirection` 扩到 8 项（`front_left` 等），判定统一走 `TouchDirection.resolve(x,y)`（45° 扇区）|
| C1 | 自定义 Key 的区域**读入**编辑器、可拖动/改尺寸、按 id 保存回 `custom.touchRegions` |

### 踩过的两个坑（都已修）

1. **`pinned` 漏写**：新建 `TouchRegionBinding` 时没给 `pinned = true`，
   而 `activeRegions` 只认 `pinned == true` → 区域写进配置却**不生效**
   （表现为"移动摇杆突然没反应"，测试用户也遇到）。
2. **惯性/绝对定位**：胶囊拖动原本用增量累加，位移会被丢弃；
   改成"DOWN 记起点 + MOVE 算绝对位置"后才 1:1 跟手。

### 已解决（C3）:自定义 Key 的摇杆无反应

**根因**（不在渲染，在**转换**）:

`TouchToCustomConverter` 把触屏的轮盘区域（槽位是虚拟的 `@move`）拿去和**组件 id 前缀**比，
可它在布局里对应的是 **`JOYSTICK_LEFT`** 那个摇杆槽位 —— 于是永远匹配不到，
轮盘区域转出来是**空绑定**。整条链路都不报错:配置合法、区域也在，只是没人可触发。

**修法**:`@move` 显式映射到 `JOYSTICK_LEFT` 转出来的组件（注意左右两个摇杆槽位都可能出现）。
回归测试见 `TouchToCustomConverterTest`。

### 11.1 数据结构

```kotlin
// TouchRegionContainerView.Item 增加:
val bindings: List<Pair<String, TouchDirection?>> = emptyList()
```

- `componentId` = 组件的 `id`（与预览里 `displayName()` 对应的那个）
- `direction` = `null`（整块区域）/ 8 向之一（仅 `MOVE_STICK` 需要）

### 11.2 行标题文案

```
按键区域 (按键 · A)
轮盘区域 (摇杆 · 左摇杆)
按键区域  未绑定 ⚠          ← 红字，避免"画着却没效果"
```

组件名一律取 `component.displayName()`（**与自定义编辑页预览一致**，不自造）。

### 11.3 文字溢出策略（用户已确认）

| 情况 | 处理 |
|---|---|
| 宽度够 | 居中整段显示 |
| 略超 | 按比例缩字号，最小 8sp，不换行 |
| 仍超 | 截断为 `A…`，**保留括号里的组件名**（信息量更大）|
| 方块极小 | 只在**拖动/选中**时画文字，平时只画色块 |

### 11.4 绑定二级页（面板内切换，不弹新窗口）

```
┌ ← 绑定「按键区域」            ┐
│        ↖   ↑   ↗             │  ← 3×3 九宫格（中心=无）
│        ←  [无]  →             │
│        ↙   ↓   ↘             │
│ 方向：↑ 上                     │
│ ☑ W   ☑ 文本…   ☐ A          │  ← 多选；BUTTON 区域**过滤摇杆组件**
│              [取消] [确定]     │
└───────────────────────────────┘
```

- 当前编辑方向：填充强调色；已配置过绑定的方向：角落小圆点
- `BUTTON` 区域：过滤 `JoystickComponent`（选了没意义）
- `MOVE_STICK` 区域：全部组件可选 + 方向必填（默认"无"= 纯推摇杆）

### 11.5 保存

写回 `custom.touchRegions[].bindings`，再走已有的 `OverlayService.refresh` + Toast。

### 11.6 验证点

1. 轮盘区域绑上摇杆组件 → 推区域，摇杆动（**同时修掉"转换后摇杆不动"**）

3. 未绑定区域显示 ⚠，且按下无反应（预期）
4. 8 向：斜推只触发斜向绑定

### 12.2 与方案原文不同的地方（都是"选了没效果"的过滤）

| 方案原文 | 实际做法 | 原因 |
|---|---|---|
| 按键区域也画九宫格 | **不画**，只写"按到就触发，不需要选方向" | 按键区域没有摇杆向量，方向判据永远不成立;画出来只会骗用户 |
| `MOVE_STICK`「全部组件可选」 | 按键 / 文本 / **触屏移动摇杆（左）** | 手柄/键盘/鼠标摇杆跟各自的输入源，绑区域没有效果;媒体组件不会按下 |
| 旧编辑器"绑定立刻落盘" | **确认后只进内存，保存退出才写** | 与拖动/删除同一套语义;「不保存退出」必须能全部反悔 |
| 行内再加一行绑定摘要 | 直接拼进区域标题（`按键区域 (按键 · A ↑)`） | 190dp 放不下第三行;而且屏幕方块与面板因此**共用同一句文案** |
| §2 的手风琴（同时只展开一行） | **未做**，每行常显滑块 | C2 基线就是这样;绑定入口已经放在第二行，不需要再点开一行才够用 |

### 12.3 交互约定（实现细节）

- 九宫格选中的是**当前编辑方向**;勾组件 = 勾出"这个组件在这个方向上的绑定"。
- 九宫格角落的小圆点 = 该方向已有绑定;中间「无」= 整块区域（按到就算）。
- 同一组件的"整块"与"具体方向"**互斥**（勾一边会清掉另一边），
  否则"整块"会把方向那条完全盖住（摘要里两条、只有一条生效）。
- 摇杆组件在选了具体方向时**灰显禁用**（它上报的是轴）。
- 组件被删后留下的失效绑定:标题回退显示 id;绑定页点「确定」时
  按"当前可见的勾选"清掉（旧编辑器也是这个语义）。
- **CPS 也按方向算了**:触摸那一路改成按**组件**记，用的就是
  "亮不亮"那份判据（`touchPressedComponents`）—— 轮盘区域上带方向的
  文本组件只在方向匹配时 +1（早先是按区域记，推任意方向都会加）。
  按键组件的物理键 CPS 仍走 `cpsBySlot`，两路相加，不会重复。

## 13. 区域辨识：序号 + 色点（2026-11-15）

### 13.1 问题

几块区域都绑同一个按键时，标题完全一样（`按键区域 (按键 · A)` × 3），
面板里**分不出哪行对应屏幕上哪块**。用户提了两个方案:给名字染色 / 加序号。

### 13.2 为什么选序号（颜色只做辅助）

| 方案 | 问题 |
|---|---|
| 名字染成方块颜色 | 面板底是 `#F3EDF7`，调色板里的蓝/绿/橙/青在这个底上对比度只有 ~2:1，11sp 很难读;调色板只有 6 个，第 7 块开始颜色重复;色弱用户直接失效 |
| **加序号** | 没有上述问题，可以一直排;色弱也能用;方块上的序号**不参与标题截断**，再小的方块也看得见 |

所以:**序号是主标识，色点是辅助**（让人能一眼扫到"哪块是蓝的"，但认人靠数字）。

### 13.3 实现

| 位置 | 做法 |
|---|---|
| `TouchRegionOrdinal.kt` | `touchRegionOrdinal(index)`：①..⑳，超过 20 退化成 `21`、`22`（㉑ 之后的字形支持不稳定）|
| `TouchRegionPalette.kt` | 调色板的**唯一来源**；面板圆点与屏幕方块都取它，不会一处改了一处不跟 |
| 面板行 | `[色点] ① 按键区域 (按键 · A)`，序号用普通深色文字（不染色）|
| 绑定页标题 | `← 绑定 ①「轮盘区域」` —— 改的是哪一块，不用退回列表确认 |
| 屏幕方块 | 左上角画序号，白字 + 黑阴影 + `clipRect` 裁进方块;**不拼进标题**，所以标题被截断时序号仍在 |
| 生效范围 | **只有自定义 Key**（触屏样式的槽位名 W/A/LMB… 本来就唯一，不加噪） |

### 13.4 取舍

- 序号按**当前列表顺序**排，删掉一块后后面的会重排；
  但面板与方块**同时**重排，任何一刻"第几行 ↔ 第几块"都是对的。
- 要"序号永久不变"就得给 `CustomTouchRegion` 加持久化字段并改编解码/兼容老配置，
  成本明显更高，暂不做。
- 色点与方块**描边色**一致（方块填充是 24% 半透明，观感会浅一些）。

### 13.5 验证

- 单元测试 4 条（`TouchRegionOrdinalTest`）：①..⑳、超过 20、20 个不重复、颜色循环。
