# 自定义 Key：触摸区域对接方案（设计稿）

> 状态:**方案讨论稿，未写代码**
> 目标:让新编辑器（单容器 + 胶囊面板）支持**自定义 Key 样式**的触摸区域 ——
> 也就是"新建区域 / 绑定组件 / 删除区域"这三件旧编辑器才有的能力。

---

## 1. 两种样式的本质区别（决定了 UI 复杂度）

| | 触屏样式（已对接） | 自定义 Key（本方案） |
|---|---|---|
| 区域从哪来 | **槽位决定**，数量与归属固定 | **用户自己加**，可增删 |
| 绑定谁 | 槽位天然对应按键 | 要**手动选组件**（按键/文本/摇杆）|
| 数量 | 5 个左右 | 用户想加多少加多少 |
| 是否需要"加/删/绑定" | ❌ 不需要 | ✅ **核心功能** |

⚠️ 所以自定义 Key 的胶囊不能只是"每行一个滑块"，还要塞进三个动作。

---

## 2. 胶囊宽度不够怎么办 —— **手风琴列表**

胶囊展开宽度固定 190dp（用户定的统一宽度）。这么窄放不下"名称 + 滑块 + 绑定 + 删除"。

方案:**行内只放摘要，点行展开细节**。

```
┌ 触摸区域                    ▾ ┐   ← 头部（点一下收起）
│ ＋ 轮盘    ＋ 按键            │   ← 两个新建按钮（sthtool 风格的小胶囊按钮）
├───────────────────────────────┤
│ ● 轮盘区域   已绑定 2 个   ▸  │   ← 行（收起态）
│ ● 按键区域   未绑定 ⚠      ▸  │
│ ● 按键区域   已绑定 1 个   ▸  │
│                               │
│   （点某一行 → 该行展开）      │
│ ● 按键区域   已绑定 1 个   ▾  │
│   ├ 大小  ────●────  28.5%   │   ← 滑块（唯一尺寸入口）
│   ├ [绑定组件]      [删除]    │
│   └ 已绑定：W  ↑ / 文本  →    │   ← 绑定摘要（可点进去改）
├───────────────────────────────┤
│              [不保存] [保存退出] │
└───────────────────────────────┘
```

要点:

| 项 | 说明 |
|---|---|
| 色点 | 与屏幕上方块颜色对应（旧编辑器就有，用户靠颜色认）|
| 绑定摘要 | **"未绑定 ⚠"必须显眼** —— 旧模型最坑的就是"画着但没绑，按了没反应" |
| 手风琴 | 同时只展开一行，避免面板变超长 |
| 滚动 | 区域多于 4 个时列表滚动（沿用现在的 ScrollView）|

---

## 3. 绑定组件:胶囊内**二级视图**

点「绑定组件」→ 胶囊内容**切换**成选择页（不是弹新窗口，避免多窗口串味）:

```
┌ ← 绑定「按键区域」            ┐
│ 当前布局里的组件：             │
│ ☑ W                            │
│ ☑ 文本「CPS」                  │
│ ☐ 摇杆（左）                   │
│                               │
│ 方向（仅轮盘区域需要）：        │
│ [无] [↑] [↓] [←] [→]          │
├───────────────────────────────┤
│              [取消] [确定]     │
└───────────────────────────────┘
```

规则（沿用旧模型的语义）:

| 区域类型 | 可绑定的组件 | 方向 |
|---|---|---|
| `BUTTON` | 按键 / 文本 / 摇杆（按下即触发）| 不需要 |
| `MOVE_STICK` | 按键 / 文本（方向匹配才算）/ 摇杆（推它）| 需要（↑↓←→）|

⚠️ 摇杆组件对 `BUTTON` 类型"不适配"（没有按下这回事），列表里要么禁用要么过滤 —— **默认过滤**，避免用户选了没效果。

---

## 4. 新建区域

- 两个按钮:`＋ 轮盘` / `＋ 按键`（对应 `MOVE_STICK` / `BUTTON`）
- 新区域默认：屏幕中央偏下、`SIZE_DEFAULT`、**自动展开该行并提示"未绑定"**
- id 生成：沿用现有的 `CustomTouchRegion` id 规则（`region_xxx`），**不要复用槽位 id**

⚠️ 不加"确认对话框"—— 加了再删就是了，弹窗只会打断节奏（旧编辑器那次"两个按钮而不是一个按钮+对话框"就是踩过闪退的坑）。

---

## 5. 删除区域

- 行展开后才有「删除」，**立刻生效**（不弹确认），但**保存退出前不写盘**
- 删除后如果列表空了，直接回到"没有区域"的空态提示 + 两个新建按钮

⚠️ 删除是"内存里删"，点「不保存退出」会全部还原 —— 与拖动/尺寸的语义一致。

---

## 6. 保存

| 动作 | 行为 |
|---|---|
| 保存退出 | 写 `custom.touchRegions` → `OverlayService.refresh()` → Toast「触摸区域已保存」|
| 不保存退出 | 不写盘，丢弃全部改动 |

⚠️ 与触屏样式共用**同一套** `pendingItems` / 快照对比逻辑，只是字段来源从 `touch.regions` 换成 `custom.touchRegions`。

---

## 7. 数据映射

| 编辑器内部 | 触屏样式 | 自定义 Key |
|---|---|---|
| `Item.id` | 槽位 id（`@move` / `W` …）| `CustomTouchRegion.id` |
| `Item.label` | 槽位名 | 「按键区域」/「轮盘区域」+ 绑定摘要 |
| 尺寸 | `TouchRegionBinding.size` | `region.size` |
| 绑定 | 无 | `bindings: List<CustomTouchRegionBinding>` |

⚠️ 需要在 `Item` 上补两个字段:`kind`（轮盘/按键）与 `bindings`（自定义 Key 用，触屏样式恒空）。

---

## 8. 实施顺序

| 阶段 | 内容 | 验收 |
|---|---|---|
| C1 | 编辑器内部 `Item` 增加 `kind` / `bindings`；自定义 Key 的读取/保存接线 | 能画出已有的自定义区域（只读）|
| C2 | 行展开 UI + 尺寸滑块 + 删除 | 能改大小、能删 |
| C3 | 「绑定组件」二级视图 + 摘要显示 | 能绑定/解绑，摘要正确 |
| C4 | `＋ 轮盘` / `＋ 按键` 新建 | 新建后能立即拖动并绑定 |
| C5 | 保存刷新 + Toast（复用触屏样式那套）| 保存后悬浮窗立刻生效 |

⚠️ 每阶段独立出包验证；**不删旧编辑器**，直到 C5 通过。

## 9. 开放问题（需要确认）

1. 绑定是**多选**还是单选？旧模型支持 `List<bindings>`（一个区域绑多个组件），胶囊里要不要保留多选？
2. 摇杆组件在 `BUTTON` 区域里**过滤掉**还是灰显？
3. 新建区域后要不要**自动展开**该行（我倾向"要"，否则用户看不到该点哪儿）？
4. 绑定二级页里，「文本」组件要不要显示它当前文字（帮助区分多个文本组件）？

## 10. 实施记录（2026-11-14）

### 已完成

| 项 | 内容 |
|---|---|
| 8 向方向 | `TouchDirection` 扩到 8 项（`front_left` 等），判定统一走 `TouchDirection.resolve(x,y)`（45° 扇区）|
| C1 | 自定义 Key 的区域**读入**编辑器、可拖动/改尺寸、按 id 保存回 `custom.touchRegions` |

### 踩过的两个坑（都已修）

1. **`pinned` 漏写**：新建 `TouchRegionBinding` 时没给 `pinned = true`，
   而 `activeRegions` 只认 `pinned == true` → 区域写进配置却**不生效**
   （表现为"移动摇杆突然没反应"，测试用户也遇到）。
2. **惯性/绝对定位**：胶囊拖动原本用增量累加，位移会被丢弃；
   改成"DOWN 记起点 + MOVE 算绝对位置"后才 1:1 跟手。

### 未解决（下次先查）

⚠️ **自定义 Key 的摇杆无反应**（用户报，原因未定）：

- 已排除:`CustomLayoutCodec` 的 `bindings` 编码/解码是完整的（读写都在）；
- 已排除:C1 保存只 `copy(region = ...)`，理论上保留 `bindings`；
- **待查**:`moveByRegion` 的来源 —— 它由 `OverlayContent` 传入，
  需要确认"区域 → 摇杆组件"的映射是否依赖 `bindings` 里的 `componentId`
  与组件的 `id` **完全一致**（转换器 `TouchToCustomConverter` 生成的 id 可能不同）。
