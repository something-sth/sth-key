# sth key

Android 按键与鼠标实时显示悬浮窗。可同时开多个窗口，外观完全可自定义，
支持 Live2D 键盘猫、自定义按键布局与 CPS 显示。

采集走 root / Shizuku 读取系统输入事件，**不注入游戏进程**。

> 应用内显示名为 **sth key**；包名为 `com.something.sthkey`。

---

## 功能

### 多重悬浮窗

每份配置各有独立开关，可以同时在屏幕上摆好几个按键窗，各自拖动、各自定位，
窗口位置与偏移互不影响。

- 每开一个新窗口会自动错开一点，不会完全盖住上一个
- 「可触摸」关掉后是纯贴图：不拦截点击，可以安心盖在游戏画面上
- 窗口不会被拖出屏幕；屏幕旋转后会留在相近的相对位置

### 三种外观样式

| 样式 | 说明 |
|---|---|
| **按键** | 内置 W / A / S / D / 鼠标键 / 空格 / Shift 布局，每个键可单独开关 |
| **自定义 Key** | 往画布上自由摆放「按键」与「文本」组件，摆成什么样就显示什么样 |
| **Live2D** | 内置「BongoCat 键盘版 / 鼠标版」，猫会跟着按键与鼠标动作 |

**按键样式**可调：颜色（按下 / 未按下）、透明度、圆角、描边、文字阴影、
字体、文字缩放、整体缩放、按下动画（无动画 / 颜色渐变 / 扩散收缩）。

**自定义 Key** 每个组件都能单独调大小、颜色、透明度、描边、圆角、文字阴影、
字体、文字缩放与偏移；组件条支持添加、复制、删除，编辑器支持撤回与恢复
（一次拖动算一步）。还可以把按键样式**一键转成**自定义 Key，位置、颜色、
透明度、字体、按下动画全部照搬。

### CPS 显示

在文字里写占位符即可：

- `(cps)` —— 一直显示数字
- `(cps2)` —— 数字为 0 时连括号一起隐藏，例如 `LMB(cps2)` 平时就只是一个干净的键名

自定义 Key 的一个组件里可以写多个占位符，每个分别统计不同的键，
编辑器会用颜色把占位符与对应的键位设置一一对应起来。

### 图片字体

除了 `.ttf / .otf / .ttc`，还能用 **Minecraft 风格的位图字体**（`ascii.png` 那类图集）：

- 直接选图片，或者选整个材质包（`.zip` / `.mcpack`，会自动从包里找图集）
- **能显示矢量字体做不到的东西**：材质包里那种自带渐变、描边、发光的像素字形
- 与常规字体是「**常规字体必选 + 图片字体可选**」的关系 ——
  图片字体只有 ASCII 字形，中文仍由常规字体显示
- 尺寸、垂直位置、每个键各自的文字偏移都能调

### 配置包

配置可导出为 `.sthkey` 分享，能连同自定义字体（含图片字体及其规格）、
Live2D 模型一起打包。
导入时会明确告知缺了哪些字体或模型，其余组件不受影响。

**也可以直接从外部导入**：在文件管理器里点 `.sthkey` 文件、或从聊天软件
分享到本应用，确认一下就能导入，不必专门跑到配置页里翻路径。

配置列表的排版可以在设置页调：是否显示描述、是否把导出/复制/删除收进
「更多」菜单、一行显示几个。

## 环境要求

- **Android 10（API 29）及以上**
- **root 或 [Shizuku](https://shizuku.rikka.app/)** —— 本项目通过读取系统输入事件工作，
  没有这两者之一无法运行
- 需要外接键盘 / 鼠标 / 手柄才有内容可显示（触屏不产生这类输入事件）

本项目**不注入游戏进程、不修改游戏文件**，但依赖系统级权限，因此
**不会上架任何应用商店**，只能通过本仓库分发。

## 安装

从 [Releases](https://github.com/something-sth/sth-key/releases) 下载 APK 安装。

首次启动会进入权限引导页，按提示授权 root 或 Shizuku 即可。

## 使用提示

- **建议先接好键盘 / 手柄再开启悬浮窗**：输入设备只在启动采集时扫描一次。
  插拔设备后到主页「工作状态」点一下「重启监听」就能重新识别
- 用 Shizuku 时请保持 Shizuku 在运行，否则采集会中断
- 遇到问题请先到「设置 → 调试」查看运行日志与诊断面板，
  那里有「CPS 自诊断」和「按键布局尺寸」两个面板，能回答大部分"为什么没显示"的问题
- 同时开太多窗会明显增加耗电（每个 Live2D 窗都在持续渲染），开超过 3 个时会提示一次

## 项目结构

```
app/src/main/java/com/something/sthkey/
├── capture/          采集层：Shizuku / root 通道、输入事件解析、悬浮窗服务
│   └── shizuku/      Shizuku 直连后端（不依赖 UserService）
├── data/config/      配置存取与编解码（JSON、.sthkey 配置包）
├── domain/           纯逻辑：配置模型、按键布局、样式解析、自定义布局
└── ui/               界面：主页 / 配置 / 设置 / 调试 / 关于
    ├── overlay/      悬浮窗渲染（Compose）
    ├── feature/      各功能页面
    └── component/    共用控件
```

`docs/` 下是各子系统的**设计依据**（为什么这么做、契约是什么、哪里不能改）。
改动对应子系统之前建议先读：

| 文档 | 内容 |
|---|---|
| [docs/shizuku.md](docs/shizuku.md) | Shizuku 通道选型、直连后端、启动策略与踩过的坑 |
| [docs/custom-key.md](docs/custom-key.md) | 自定义 Key 的布局模型与坐标系 |
| [docs/multi-overlay.md](docs/multi-overlay.md) | 多重悬浮窗、位置与边界 |
| [docs/live2d.md](docs/live2d.md) | Live2D 样式契约与模型处理 |
| [docs/bitmap-font.md](docs/bitmap-font.md) | 图片字体（Minecraft 位图字体）：格式规范、截取算法、缩放与阴影，以及踩过的坑 |
| [docs/config-package.md](docs/config-package.md) | 配置包（`.sthkey`）：包结构、导出/导入、外部分享导入的接法 |

## 构建

需要 **JDK 25** 与 Android SDK（`compileSdk 37`）。

```bash
# 单元测试
./gradlew :app:testDebugUnitTest

# Debug 包
./gradlew :app:assembleDebug

# Release 包（未签名，需要你自己配置签名）
./gradlew :app:assembleRelease
```

在项目根目录建 `local.properties` 指向你的 SDK：

```properties
sdk.dir=/path/to/Android/Sdk
```

> `local.properties` 已在 `.gitignore` 中，不要提交。

代码里有相当多的中文注释，写的都是**为什么这么做**（包括踩过的坑），
而不是复述代码在做什么。改动前建议先读一读对应位置的注释。
